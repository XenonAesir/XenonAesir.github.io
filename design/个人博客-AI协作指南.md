# 个人主页博客 · AI 协作指南

> 技术栈：pnpm + Next.js (App Router) + TypeScript + Tailwind CSS + shadcn/ui + Lucide + MDX，部署 Vercel
> 核心原则：**你给目标和验收标准，让 agent 决定实现步骤；一次只做一个能验证的增量。**

---

## 一、开口前先定三个决策

这三件事决定 agent 给你什么方案。**先定，再问。**

### 1. 内容怎么存 → 本地 MDX 文件，不上数据库
个人博客的文章就是文件，放进仓库，Git 就是版本管理。数据库只会增加复杂度，不带来任何收益。

### 2. 要不要登录 / 后台 → 不需要
纯展示型博客**不需要** Better Auth、Drizzle、tRPC。它们是给"有用户、有数据交互"的应用准备的。

> 如果你的真实目标是**练这套栈**，把 tRPC / Drizzle / Better Auth 放到**第二阶段**（留言板、订阅、后台编辑器）。别和"先跑通一个博客"混在一起——混在一起的结果是第一个页面一周都出不来。

### 3. 怎么部署 → Vercel
Next.js 官方最佳适配，推代码自动构建上线。个人博客免费用量绰绰有余。

---

## 二、第一条消息：先要计划，不要代码

直接复制：

```
我要从零做一个个人主页博客，技术栈固定：
pnpm + Next.js(App Router) + TypeScript + Tailwind CSS + shadcn/ui + Lucide，
内容用 MDX 本地文件，不上数据库，最后部署到 Vercel。

页面需求：
- 首页：头像、简介、社交链接、最新 3 篇文章
- /blog：文章列表
- /blog/[slug]：文章详情，带代码高亮
- 深色模式 + 移动端适配

先不要写代码。请给我：
1) 目录结构
2) 依赖清单及各自作用
3) 分步实施计划，每步的验收标准

我是这套栈的新手，每步请简短说明"为什么这样做"。
```

**三个关键句**：
- `先不要写代码` —— 防止它一次生成 20 个文件
- `每步的验收标准` —— 给你可检查的东西，而不是"完成了"
- `我是新手，解释为什么` —— 否则你只会拿到能跑但不理解的代码

## 三、迭代节奏：每轮只推进一步

| 轮次 | 你说什么 | 验收标准 |
|---|---|---|
| 1 | 按你的计划，先搭骨架 | `pnpm dev` 能打开首页 |
| 2 | 接 MDX 读取，先放 2 篇示例文章 | 列表页和详情页能正常显示 |
| 3 | 用 shadcn/ui 重做导航和卡片，加深色模式 | 手机宽度下不错位 |
| 4 | 跑 `pnpm build`，有错就修到通过 | 构建 0 error |
| 5 | 部署到 Vercel，告诉我需要哪些环境变量 | 线上能正常访问 |

### 每轮结尾固定加一句

> **改完请运行 `pnpm build`，把报错原样贴出来；构建通过后再告诉我你改了哪些文件。**

这句话能挡掉 agent 最常见的假完成——"我改好了"其实根本没编译过。

### 每步做完自己检查

- 它是真的能跑，还是"应该能跑"？
- 我能不能用自己的话解释这一步做了什么？
- 有没有引入我没要求的东西（登录、i18n、测试框架）？

## 四、针对这套栈的四个具体提醒

### 1. 让它用 shadcn 的 CLI，不要手写组件
```bash
pnpm dlx shadcn@latest add button
```
shadcn/ui 的机制是**把组件源码复制进你的仓库**，不是 npm 依赖。手写等于白费它最大的价值（源码归你、可随意改）。

### 2. 小众库必须先查文档
这让模型容易编造 API 的库：**pi、Uniwind、HeroUI Native、Rsbuild**。
要求它：**先核对官方文档，再写代码；不确定的地方明确说"不确定"，不要猜。**

Next.js / React / Tailwind / shadcn 是 GitHub 高频栈，模型见过成千上万个例子，可以直接写。

### 3. MDX 不在原技术清单里，让它给选型理由
推荐方向：`next-mdx-remote`（轻量、App Router 友好）或 Content Collections（类型安全）。
**要求它说明为什么选这个、代价是什么**，别默默选一个。

### 4. 明确禁止扩范围
在提示词里加一句：

> 这一阶段**不需要**：用户登录、数据库、i18n 多语言、单元测试框架、CI 配置。除非我明确要求，不要添加。

## 五、不要这样问

| ❌ 错误问法 | 为什么不行 | ✅ 改成 |
|---|---|---|
| 「帮我做一个博客」 | 目标太宽，一次生成几十个文件，跑不起来 | 参考第二节的结构化首问 |
| 「用所有最新技术栈做博客」 | tRPC + Drizzle + Better Auth 全塞进来 | 先跑通静态博客，分阶段加 |
| 「这样对吗？」 | 得到的是安慰，不是检查 | 「按验收标准逐条检查，不满足的列出来并修」 |
| 「再优化一下」 | 不知道优化什么，容易改坏 | 「首屏 LCP 超过 2.5s，找出原因并优化」 |

## 六、第二阶段可以加的（可选）

跑通博客之后，如果目的是练这套栈：

1. **留言板** → tRPC + Drizzle + PostgreSQL（或 Neon）
2. **订阅** → Better Auth（登录）+ Zod（表单校验）
3. **AI 摘要 / 问答** → pi-ai（统一多模型调用）+ TanStack Query
4. **工程化** → Biome（lint+format）、Vitest（测试）、PGLite（测试用数据库）

每次只加一层，每层都要能跑通 `pnpm build` 再加下一层。

---

## 七、一句话总结

> 把 agent 当**会写代码的实习生**来带——给目标、给边界、给验收，别让它自由发挥。
> 跑通一个能看的博客，再逐层加数据库和 tRPC，才学得会。
